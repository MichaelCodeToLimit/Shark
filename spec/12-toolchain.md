# 12 — The Toolchain: `compose`

*Edition 2026. **[N]** normative, **[I]** informative.*

One tool. No separate package manager, formatter, test runner, doc generator or build
script language.

---

## 12.1 Command surface **[N]**

```
compose                            build in dev mode
compose release                    build optimised
compose extreme                    build with maximum optimisation
compose run [-- args]              build then run
compose check                      analyse without producing a binary
compose test [filter]              build and run tests
compose format [paths]             normalise layout
compose doc                        generate documentation
compose new <name>                 create a project
compose add <package> [version]    add a dependency
compose remove <package>           remove a dependency
compose update [package]           update the lockfile
compose publish                    publish to the Reef
compose bundle                     produce a platform package
compose target <list|add|remove>   manage cross targets
compose registry <list|show|check|why>
compose locale <new|check|coverage|list>
compose translate <file> --to <locale>
compose explain <topic>            storage, schedule, vectorisation, transfers, bounds, <code>
compose audit                      trusted modules, foreign calls, secrets, licences
compose clean
compose version
```

### 12.1.1 Global options **[N]**

```
--target <triple>          --locale <tag>            --edition <year>
--jobs <n>                 --offline                 --frozen
--message-format <human|json|short>
--colour <auto|always|never>
--print-hash               --verify-reproducible
--time-report              --memory-budget <bytes>
```

## 12.2 The manifest: `project.shark` **[N]**

The manifest is written in Shark, using the same grammar, parsed by the same parser.
There is no TOML, YAML or JSON.

```shark
this is edition 2026

the project is called tel aviv hub
  version 0 4 1
  described as A neighbourhood noticeboard
  by Michael Davies
  licensed as MIT

source is in src
tests are in tests
assets are in assets

locale english

targets
  x86 64 windows
  wasm32 browser

depends on
  plotting version 2 1
  markdown version 0 9 from the reef
  local widgets from the folder ../widgets
  fast json version 3 from github example fast json at tag v3 0 2

for release
  deny promotions in hot paths
  keep debug information no

for tests
  fixed seed 20260922
```

### 12.2.1 Version syntax **[N]**

Versions are written as words of digits: `version 2 1 4` means 2.1.4. A dependency
requirement `version 2 1` means "compatible with 2.1", i.e. `>= 2.1.0, < 3.0.0`, using
semantic versioning. Exact pins: `version exactly 2 1 4`.

## 12.3 The lockfile: `project.lock` **[N]**

Generated, committed, machine-written:

```shark
note generated by compose. do not edit.
locked

  plotting version 2 1 7
    from the reef
    content hash b3 9f4c1e7a20ab...
    canonical hash b3 44de91c0ff31...

  markdown version 0 9 3
    from the reef
    content hash b3 12ab98cd...
    canonical hash b3 77aa2210...
```

Two hashes per dependency:

- **content hash** — of the source archive; guarantees you got the same bytes.
- **canonical hash** — of the dependency's SIR-C ([doc 08 §8.7](08-sir.md)); guarantees
  you got the same *program*, even if the bytes were reformatted or translated to another
  locale.

`compose --frozen` fails if the lockfile would change. CI uses it.

## 12.4 Packages and the Reef **[N]**

- The public registry is **the Reef** (`reef.shark-lang.org`).
- A package is a project with `shared` items and no `to start`.
- Names are namespaced: `by michael davies package widgets`, with a short alias declared
  by the owner once (`widgets`). Alias squatting is prevented by requiring a published
  version before an alias is granted.
- Every published version is immutable. Yanking marks a version unusable for new
  resolutions without breaking existing lockfiles.
- Publishing requires a signed manifest; the Reef records a transparency log (a
  Merkle tree, publicly auditable) so a compromised registry cannot serve a different
  artefact to one user.
- `compose audit` reports, for the whole dependency graph: trusted modules, foreign
  declarations, `a secret called` sites, licences, and known advisories.

### 12.4.1 Resolution **[N]**

Minimal version selection: `compose add plotting 2 1` records `2 1` and resolves to the
**lowest** version satisfying every constraint in the graph. This makes builds stable by
default; `compose update` raises versions deliberately. Duplicate major versions of the
same package may coexist; duplicate *minor* versions may not.

## 12.5 Modules and imports **[N]**

- `src/main.shark` is the entry module. It must declare `to start` or contain a `page`
  marked `the first page`.
- A file at `src/ui/panels/side.shark` is the module `ui panels side`.
- `use ui panels side` imports it; `use plotting charts` imports from a dependency.
- `share` exports.

```shark
note src/ui/panels/side.shark
share a side panel

page a side panel
  in a column
    show text Filters
    ...
```

There are no circular-import restrictions for types and signatures; module-level value
initialisation must be acyclic.

## 12.6 `compose format` **[N]**

Normative behaviour — the formatter has **no options** (one style, ends the argument):

1. Indentation: the project's unit, default 2 spaces.
2. Flush single-action bodies ([doc 02 §2.6.2](02-grammar.md)) are rewritten to indented
   bodies.
3. One blank line between top-level declarations; none at the start of a block.
4. `note doc` lines are kept attached to their declaration.
5. Trailing separators are removed; a final newline is added.
6. For RTL locales, no bidi controls are inserted into source
   ([doc 01 §1.8](01-lexical-structure.md)).
7. The formatter MUST NOT change the canonical hash. This is checked by
   `compose format --verify`, and is a conformance test.

## 12.7 Dev loop and hot reload **[N]**

```bash
compose run --watch
```

- Rebuild is incremental ([doc 09 §9.2](09-compiler-pipeline.md)).
- The runtime keeps a live SIR-D image. On rebuild, `compose` diffs SIR-D:
  - **body-only change to an action or handler** → swap the compiled function; state is
    preserved;
  - **view change in a page** → re-render; state preserved;
  - **style change** → re-render; no recompilation of logic;
  - **record field added with `starting at`** → migrate live values;
  - **anything else** (field removed, type changed, signature changed) → full restart,
    with the reason printed.
- Hot reload is a dev-mode-only feature and is never present in release binaries.

## 12.8 Testing **[N]**

```bash
compose test                         # all
compose test damage                  # name filter
compose test --module game
compose test --repeat 100            # property tests, more cases
compose test --seed 20260922
compose test --coverage
```

- Tests are handlers with disjoint state and run in parallel by default
  ([doc 07 §7.3](07-concurrency-and-simd.md)); a test that touches shared state is
  serialised automatically, not by an attribute.
- Determinism ([doc 07 §7.5](07-concurrency-and-simd.md)) means a failing test always
  reproduces with its printed seed.
- Coverage is by SIR-C block, mapped back through the source map, so it is accurate for
  multi-clause lines and for translated sources.
- Snapshot testing of views:

```shark
a test called the profile page looks right checks
  expect the view of page Profile to match the snapshot
```

## 12.9 Record and replay **[N]**

```bash
compose run --record session.sharkrec
compose replay session.sharkrec
compose replay session.sharkrec --to handler 4412       # step to a handler invocation
```

Recording captures every non-deterministic input: clock reads, entropy draws, network
responses, file reads, input events. Replay is exact because everything else is
deterministic. This is the primary debugging tool and replaces most use of a stepping
debugger; a conventional debugger is still available via DWARF/PDB.

## 12.10 Documentation **[N]**

`compose doc` produces a static site from:

- `note doc` comments;
- signatures, with their slots, terminators, effects, result types and inferred slot
  modes;
- every locale alias of every shared name;
- examples extracted from tests marked `a test called … checks` whose name begins with
  `example`.

Signatures are rendered in the reader's chosen locale, with a locale switcher — the same
mechanism as `compose translate`.

## 12.11 Assets **[N]**

```bash
compose assets
```

Converts source assets (PNG, glTF, WAV, TTF) into packed, target-appropriate formats
(BCn/ASTC textures, packed meshes, streaming audio, subsetted SDF fonts) with a content
hash, and generates a typed module so assets are referenced by name, not by string path:

```shark
use assets

draw hero sprite at player position
```

A missing asset is a compile error, not a runtime 404.

## 12.12 Toolchain installation and pinning **[N]**

```bash
curl -sSf https://shark-lang.org/install | sh
compose version
```

A project may pin the toolchain:

```shark
needs compose version 1 4 or newer
```

`compose` is a thin launcher that downloads and caches the exact pinned toolchain, so a
project builds identically on any machine and in CI without a separate version manager.

## 12.13 CI recipe **[I]**

```yaml
- run: compose --frozen check
- run: compose --frozen test
- run: compose --frozen format --verify
- run: compose --frozen registry check
- run: compose --frozen audit --deny-new-trusted
- run: compose --frozen release --verify-reproducible
- run: compose --frozen translate src/main.shark --to hebrew --verify
```

The last line is worth having in any multilingual project: it proves that the Hebrew
translation of your source still compiles to the identical program.
